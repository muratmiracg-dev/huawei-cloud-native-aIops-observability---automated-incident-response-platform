## LinkedIn project entry

**Project Name:** Huawei Cloud-Native AIOps, Observability & Automated Incident
Response Platform

**Tools Used:** Huawei Cloud CCE, SWR, OBS, AOM, LTS, Cloud Eye, Python, FastAPI,
Scikit-learn, OpenTelemetry, Prometheus, Grafana, Tempo, Docker, Kubernetes,
Helm, Terraform, GitHub Actions, Pytest, Ruff, Trivy, CodeQL, k6, YAML

**Description:**

- Developed an end-to-end cloud-native AIOps and Site Reliability Engineering
  platform that detects operational anomalies, explains likely root causes and
  coordinates safe, auditable incident response for Huawei Cloud CCE.

- Built four observable FastAPI services covering catalog, orders, payments and
  the AIOps control plane, with health probes, structured logging, Prometheus
  metrics, distributed tracing, idempotency and controlled failure injection.

- Created a vendor-neutral telemetry pipeline with OpenTelemetry, Prometheus,
  Tempo and Grafana. Designed three dashboards with 22 panels covering
  availability, latency, SLO burn rate, error budgets, anomaly intelligence,
  incidents and automation outcomes.

- Engineered an explainable hybrid anomaly model combining robust median/MAD
  scoring with Isolation Forest. Added evidence-based root-cause ranking,
  severity thresholds, confidence scoring and synthetic incident replay.

- Implemented a guardrailed incident-response engine with dry-run defaults,
  namespace-scoped Kubernetes RBAC, service allow lists, replica ceilings,
  cooldowns, risk policies and auditable scale-up, circuit-breaker and
  degraded-mode actions.

- Prepared secure Kubernetes and Helm deployment packages with non-root
  workloads, read-only filesystems, probes, HPA, PDB and NetworkPolicy. Authored
  Terraform for VPC, subnet, CCE, private SWR repositories and versioned OBS
  storage.

- Established DevSecOps quality gates using GitHub Actions, Pytest, branch
  coverage, Ruff, Helm validation, Terraform validation, Trivy and CodeQL.
  Delivered 36 passing tests with 93.76% coverage, six operational runbooks,
  four architecture decisions, two 20-slide presentations and a 20-page
  vector-HD executive report.

The result connects observability, ML-assisted diagnosis, SLOs and bounded
automation in a deployment-ready reference architecture. Live provisioning
requires authorization, security review and cost approval.
